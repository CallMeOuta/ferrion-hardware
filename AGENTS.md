# ferrion-hardware

Every driver of FerrionOS and its support for the machines it runs on, physical and virtual alike (laptops and desktops, hypervisors such as QEMU/KVM, VirtualBox, VMware and Hyper-V, and cloud instance types): FerrionOS's own drivers under `drivers/` (FerrionOS's ADR 0047), the Linux driver host under `driver-host/` (ADR 0046), and per-machine profiles under `profiles/`. Everything else of FerrionOS is in the FerrionOS repository, which pins this one by commit. Before working here, read FerrionOS's `AGENTS.md`, `CONTRIBUTING.md`, and ADRs 0046 and 0047; every rule there applies here: no comments in FerrionOS's own code (license notices and the source notice of brought-in code stay), TigerStyle bounds (ADR 0024), no agent-written unit tests (ADR 0025: proof is a VM check in FerrionOS's `scripts/vm-test.py`, a differential test or a deterministic simulation), measured targets in commit messages (ADR 0026), the naming rule, and the security rules.

Rules of this repository:

- Licensing: the whole repository is GPL-2.0-only, the license of Linux's drivers, so no driver here can be made proprietary. A new file of FerrionOS's own starts with the line `SPDX-License-Identifier: GPL-2.0-only` in the file's comment syntax (a license notice, which FerrionOS's comment rule keeps). Code brought in under another license keeps its own notice and names its source and commit. Check with `python3 scripts/license-check.py check origin/main`.
- `drivers/`: FerrionOS's own drivers. Type-check alone with `cd drivers && cargo check -Zbuild-std=std,panic_abort --target x86_64-unknown-redox -p <driver>`, update the pinned FerrionOS revision with `scripts/ferrion-rev.sh`, and check or merge upstream changes with `scripts/drivers-upstream.sh`. A change that also needs a change in the FerrionOS repository lands as paired commits, each naming the other, and FerrionOS's pin moves only to a commit whose drivers pass FerrionOS's checks against FerrionOS's current tree. The libraries drivers share (block, network, graphics, PCI, virtio) live here under the same license, so a driver built on them is GPL too.
- `driver-host/`: Linux's files are byte-exact copies of the pinned 6.18.y release, under `driver-host/linux/` with their paths. A changed line is a patch file with its reason, never an edit in place. Code taken from FreeBSD's LinuxKPI or OpenBSD keeps its notice and names its source and commit. An interface the shim does not provide ends the host with its name; nothing missing answers success.
- `profiles/<vendor>/<model>/`: one machine per folder. Before editing a profile, read `python3 scripts/profile.py schema`; handwrite driver start files, import evidence with `profile.py evidence import`, regenerate with `profile.py readme` and `profile.py index`, and run `profile.py check --drivers DIR --checks FILE`. A "works" entry cites its check and run; absent evidence says "not shown". Public evidence names QEMU's version only and calls a 3D renderer `host GPU`. The maintainer's machines have no public profile until the maintainer says so; no profile, README or commit names them.
- Commits: commits of FerrionOS's own (the maintainer's and its agents') carry author and committer `CallMeOuta`. An outside contribution carries the contributor's own name and e-mail as author, with the maintainer as committer (FerrionOS's repository keeps its one identity); no attribution lines, "Category: Description" subjects of at most 72 columns, the numbers before and after in the body.
